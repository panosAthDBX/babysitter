# OMP Concurrent-Effects Parity and Babysitter Process Readiness — Design Specification

Status: **Draft 15 — final clean normative cutover; specification only; verified-live and proposed surfaces are explicitly separated; no implementation or launch is authorized**
Owner: Runtime/SDK
Scope: read-only OMP agent/skill concurrency and deterministic readiness proof

## 0. Decision and boundary

Version one has two bounded deliverables, in order:

1. authenticated, source-ordered Babysitter delivery through OMP's existing blocking native `{ context, tasks[] }` batch for configured read-only `agent` and `skill` groups; and
2. a deterministic readiness pipeline for one selected process, exact source/configuration chain, installed adapter/OMP, pilot, failure proof, approval, and fresh launch.

OMP keeps native per-item spawning, the existing finite native worker pool, and its session-scoped semaphore. The authenticated per-batch bound limits that worker pool. This design adds no host-global scheduler, ordinary-task migration, idle-capacity reservation, persistent worker loop, shell concurrency, parallel write, active per-item cancellation, or serial fallback.

`execution-manifest.json` is only a logical/rendered name for a content-addressed artifact. The specification kind is `design-markdown`. Draft 15 is the sole contract; there are no compatibility aliases, serial fallback, or implicit capability advertisement.
The only capability in scope is closed `HarnessCapability.ConcurrentEffects`. `BackgroundEffects`, `MultiHarnessDispatch`, canonical graph artifacts, graph compilation, shell concurrency, and generalized workflow execution are explicitly out of scope and cannot appear in declarations, discovery, dispatch, conformance, or failure registries.

OMP proposes `registerTrustedTaskBatchGrantV1(request): Promise<{requestSha256:string}>` and `consumeTrustedTaskBatchGrantV1(scopeId,toolCallId,normalizedEnvelope): Promise<ConsumedTaskBatchGrantV1>`. Registration is create-or-return on `(scopeId,toolCallId,registrationGeneration)`. Consumption first canonicalizes the complete normalized live envelope, including shared context and every ordered item name/agent/task/output-schema byte/schemaMode/effort/isolated field; only then may it consume. Identical return-crash replay returns the same consumed batch; partial, reordered, stale, expired, or conflicting replay rejects without consuming another grant. It returns only host-private per-item grants. Private fields are never added to prompt/transcript objects and are stripped before child construction.

The executor acquires in order: call-local permit, live session-semaphore permit, then the proposed shared `SessionCapacityFenceV1`. Settings mutation/semaphore resize acquires the same fence. Under that fence the executor performs a post-acquire reread of settingsRevision/capacity and compares the consumed grant. Match linearizes item entry; mismatch releases both permits before leaving the fence, writes authenticated pre-entry failure, and fences every remaining queued item. `settingsRevision` and this shared fence are proposed OMP state, not verified live behavior. The batch grant never resizes/reserves the semaphore; all permits release in `finally`.
V1 requests `restrictToolNames=['glob','grep','read','yield']`. `yield` is implemented only as `submitAuthenticatedYieldV1(capability,canonicalOutputBytes)`: host verifies the bound item/output-schema, atomically stores the protected result, and consumes the one-shot capability; it exposes no filesystem, provider, discovery, or mutation authority. `glob`,`grep`,`read` use only `ReadOnlyVfsCapabilityV1`: relative NFC paths beneath the already-open immutable-snapshot root; absolute, `~`, dot/traversal, symlink/hard-link alias, extra root, and local/internal/URL scheme reject. The snapshot is retained through completion; no lease alternative. Shell/write/network/task/apply/merge, extension/MCP discovery, and writable isolation are denied. Native conformance tests every read-tool escape/mutation and yield result-only behavior.

The proposed owner is `packages/trust-core/src/readiness/`; the external authority implements the same transaction semantics in its own serialization domain.

## 1. Normative notation and trust boundary

TypeScript notation is normative. Every interface is closed: every field is required unless its type includes `null`; unknown fields and enum values reject. JSON counts, offsets, durations, epochs, and generations are finite safe integers unless explicitly encoded as decimal strings. Hashes and HMAC-SHA-256 values are lowercase, exactly 64-character hexadecimal. Ed25519 signatures are unpadded RFC 4648 base64 of exactly 64 signature bytes; public-key fingerprints are lowercase SHA-256 hex of the canonical 32-byte public key. Any other lexical encoding rejects before hashing.

type UnsignedNs = string; // lexical grammar: 0|[1-9][0-9]*; numeric range [0,2^128-1]
A canonical timestamp is UTC RFC 3339 with exactly three fractional digits (`YYYY-MM-DDTHH:mm:ss.sssZ`). Every field whose name ends in `MonotonicNs` or `SpanNs`, including nullable fields, has type `UnsignedNs`; no plain-string exception exists. An `UnsignedNs` is compared as an integer, never lexically or through floating point. A positive span has `start < finish`. All authenticated activity intervals are half-open `[start,finish)`; at equal endpoints, finishes are processed before starts.

The host-protected root is OMP-owned, outside workspaces and run directories, and unavailable to worker tools. It stores keys, immutable objects, retained-byte capabilities, and append/CAS ledgers. Run-directory bytes, worker prose, and rendered task output are non-authoritative. H0/H1/H2 and D0/D2 run from pinned installed bytes. Deterministic validators decide every mechanical gate. Approval cannot waive failure. Stored READY is historical; live READY additionally requires current authority, revocation, trusted time, clock floor, lock, and sealed-input verification.

## 2. Canonical bytes, paths, retained inputs, and installed bytes

### 2.1 Canonical JSON and cryptography

`canonicalizeReadinessJsonV1` is RFC 8785 JCS over Unicode-scalar JSON with UTF-8 only, no BOM, no duplicate key before parsing, no unpaired surrogate, no non-finite or negative-zero number, and safe integers for integer fields. A decimal policy value is represented by `RationalV1`, not a JSON number. Canonical bytes have no trailing LF; a stored JSON file is those bytes plus one LF.

```text
SEM(D,P) = SHA256(ASCII(D) || 0x00 || canonicalizeReadinessJsonV1(P))
MAC(D,P,K) = lowercase_hex(HMAC-SHA-256(K, ASCII(D) || 0x00 || canonicalizeReadinessJsonV1(P)))
RAW(B) = lowercase_hex(SHA256(B))
SIG(D,P,SK) = unpadded_base64(Ed25519.Sign(SK, ASCII(D) || 0x00 || canonicalizeReadinessJsonV1(P)))
```

Every domain below is literal lowercase ASCII. A MAC is computed with both its MAC field and final hash field omitted; the final semantic hash includes the MAC and omits only the final hash. A signature is computed with signature and final hash omitted; the final hash includes the signature and omits only the final hash. Other semantic objects omit only the registry-listed field. There is no inference or generic fallback. Key selection is exact: every H0/H1/H2/A2/admission/time-head/authority-pointer/revocation-head/readiness-object-store MAC, including `ProtectedInvocationByteObjectV1.objectMac`, uses the sole `RuntimeSecurityPinsV1.resultAuthenticationKeyId`; every launch MAC uses the sole `RuntimeSecurityPinsV1.launchAuthenticationKeyId`. The verifier resolves either ID only through the pinned verifier manifest and retention policy. A linked record inherits the same key ID as its genesis. Result-key retention is live-reference extended through terminal H2/A2 reconciliation; launch-key retention is live-reference extended through terminal launch cleanup/outcome. Loss before the corresponding terminal commit is a protected-byte availability failure, never key unavailability; a missing required retained key otherwise rejects.

### 2.2 Descriptor-relative paths and immutable handles

`FilesystemIdentityV1.stDevDecimal` and `stInoDecimal` are the unsigned base-10 `0|[1-9][0-9]*` renderings of POSIX `stat.st_dev` and `stat.st_ino` obtained from the already-open no-follow descriptor; leading zero, sign, hexadecimal, platform alias, path-derived ID, or other encoding rejects. Unsupported non-POSIX identity sources reject. Both root and sealed-object identity use this one extraction.

An inventory is `canonicalizeReadinessJsonV1(entries)`, where each directory is exactly `{"relativeLocator":L,"entryKind":"directory"}` and each file is exactly `{"relativeLocator":L,"entryKind":"regular-file","byteLength":N,"executable":B,"rawSha256":H}`. Entries are sorted by `L` UTF-8 bytes and duplicate locators reject; there are no omitted-field placeholders or other shapes. `inventorySha256=RAW(canonical inventory bytes)`. `RootObjectIdentityV1` is computed before and independently of any handle binding. A binding references that root identity and can therefore never participate in the sealed-object cycle. A locator names a proper descendant; the root itself is named only by `RootObjectIdentityV1`.
For a regular descendant, `contentIdentitySha256=RAW(file bytes)`. For a directory descendant it is `RAW` of the same canonical recursive inventory rooted at that descendant. These are the only content rules.

A descriptor-relative locator is canonical and resolved no-follow from its open base. Symlinks, junctions, aliases, special files, and regular files with `st_nlink>1` reject; directory link counts are ignored because POSIX `.`/`..` make them greater than one. Directory aliasing rejects when two distinct inventory locators resolve to the same `FilesystemIdentityV1`. Every used object remains sealed through last use and paths are never reopened.

Byte ranges are half-open raw UTF-8 offsets. A call slice is exactly the parser `CallExpression` from the first byte of `ctx` through the byte after `)`. A metadata slice is exactly the metadata object-expression node supplied to that call. A barrier slice is the immediately adjacent executable sibling statement, or the enclosing block's zero-width entry/exit boundary. Comments and empty statements are trivia; no executable sibling may be skipped. Both barriers are mandatory.

The only CLI filesystem locator is `generate --config`, relative to checkout base. Readiness payloads, retained lock wrappers, approval inputs, and launch requests are content-addressed `ReadinessObjectRefV1` values plus protected-ledger semantic hashes; no lock-root, ambient path, or absolute path exists.
Every durable object containing a monotonic timestamp/deadline is atomically accompanied by `DurableMonotonicBindingV1` to the active boot/clock epoch. Recovery may compare counters only under the same epoch; mismatch immediately takes the object's defined expiry/operator-attention terminal path and never creates a fresh lease/deadline.

Every non-embedded semantic object (evidence, specialized Pilot/failure/review results, protected snapshots, payloads) is stored as canonical bytes and atomically indexed by `SemanticObjectIndexV1` from its semantic hash to exact `ReadinessObjectRefV1`; conflict rejects. Envelopes/transitions/pointers and semantic indexes live in the protected ledger. The byte store is physically outside and explicitly excluded from every `RootObjectIdentityV1` inventory; its capability binds the static authority root containing only store policy/key metadata, never stored objects. Thus every semantic hash is locatable and no root/store cycle exists.
Artifact `createdAt` is nonce-fresh trusted time and `expiresAt=createdAt+evidenceRetentionMs`. For each result-key-authenticated artifact, key-verifiability end is at least `max(expiresAt,createdAt+resultKeyRetentionMs)`; protected live-operation references extend it through their monotonic retained-until/terminal reconciliation. Launch key baseline is authorization time plus `launchKeyRetentionMs` and live references extend through cleanup/outcome. Checked arithmetic and live rejection of expired/unverifiable material are mandatory.

`ArtifactEnvelopeV1.artifactKind` selects exactly one payload target and exactly one stage: `bootstrap→BootstrapPayloadV1/DRAFT`, `execution-manifest→ExecutionManifestV1/GENERATED`, `generation-rejection→GenerationRejectionPayloadV1/REJECTED`, `launch-descriptor→LaunchDescriptorArtifactPayloadV1/GENERATED`, `static-validation→StaticValidationPayloadV1/STATIC_VALIDATED`, `adapter-capabilities→AdapterCapabilitiesPayloadV1/STATIC_VALIDATED`, `adapter-conformance→AdapterConformancePayloadV1/ADAPTER_VALIDATED`, `pilot-results→PilotResultsPayloadV1/PILOT_VERIFIED`, `failure-matrix→FailureMatrixPayloadV1/FAILURE_VERIFIED`, `fitness-evaluation→FitnessEvaluationPayloadV1/FITNESS_ACCEPTED`, `cleanup-intent→CleanupPayloadV1` with `kind='intent'` and the owning readiness-stage predecessor's stage, `cleanup-proof→CleanupPayloadV1` with `kind='proof'` and the same owning stage, `lock-manifest→ReadinessLockPayloadV1/LOCKED`, `lock-rejection→LockRejectionPayloadV1/REJECTED`, `approval-import→ApprovalImportPayloadV1/LOCKED`, and `readiness-decision→ReadinessDecisionPayloadV1` with stage equal to its `liveState`. No other kind/stage/payload combination is valid.

Non-cleanup artifact envelopes are unique by `(artifactKind,readinessId)` and require `operationId=null`; cleanup envelopes are unique by `(artifactKind,readinessId,operationId)` and require nonempty operation ID. Envelope readiness ID equals the selected payload readiness ID, every input envelope readiness ID, and transition readiness ID. Cleanup intent requires `observedAbsent=null`; proof requires boolean and exact equality of readinessId, operationId, and materialization identity with its sole intent input. Payload raw/semantic hashes and complete ordered inputs must verify.
Each operation first create-or-returns `CleanupMaterializationIndexV1` for the actual sealed object it creates; intent/proof materialization hash resolves that index and envelope/payload/index operation IDs are equal. Proof binds absence of that indexed object only.
Authoritative transitions are exact. DRAFT→GENERATED uses execution manifest; GENERATED→STATIC_VALIDATED requires static pass; STATIC_VALIDATED→ADAPTER_VALIDATED requires adapter-capabilities `{declaredCapability:'ConcurrentEffects',privateConformanceModeEnabled:true,publicConcurrentEffectsAdvertised:false}` plus native conformance exact/allPassed/publicAdvertisementAuthorized; only the committed successor may publish public advertisement. Later pass branches are Pilot→Failure→Fitness→Lock→final decision. Every false gate transitions to REJECTED with its attempted artifact; readiness/launch conformance cannot alter ADAPTER_VALIDATED or public native advertisement.
For every pre-LOCKED branch, snapshot cleanup/authority/time/floor refs are null; decision is pass for success and reject for rejection, with rejectionKind null on pass and exact payload rejection kind (or `stage-failed-v1`) on reject. For LOCKED→final, cleanup refs remain null, authority/time/floor equal the readiness-decision payload, decision equals liveState (`pass|reject|operator-attention`), and rejectionKind is null only for READY. No other field combination hashes.

Immutable objects precede one pointer CAS and recovery follows the unique chain. Competing valid heads return terminal `competing-heads-v1` to the caller without inventing an unavailable readiness transition or mutating the pointer; the enclosing stage emits its ordinary failed artifact when constructible.

## 10. Exact fitness and deterministic decision

Rational numerator matches `0|[1-9][0-9]*`, denominator `[1-9][0-9]*`, gcd one, zero only `0/1`; thresholds are nonnegative. WR = max(0,C_ns-S_ns) / S_ns
```text
C_ms = C_ns / 1,000,000
AE = abs(C_ms-E_ms)
ER = AE / E_ms
```

## 14. Stable acceptance

- Gate 1 has the least-privilege protected substrate, complete normalized native batch-grant register/consume seam, one-shot host-private item grants, post-acquire linearizable capacity fence, unchanged session semaphore, and source-ordered all-settled results.
- Concurrent children receive one immutable-snapshot, descriptor-confined VFS; only read/glob/grep and authenticated result-only yield are enabled. Writable isolation and every path/tool/scheme escape fail conformance.
